# ADR 0006: Cloudflare Durable Objects 및 KV 기반 분산 세션 아키텍처

## 상태
승인됨 (2026-09-26)

## 맥락
- 서버리스 엣지 환경에서 인스턴스(isolate) 분산으로 인해 인메모리 세션이 분절되어 404 오류가 발생할 수 있음.
- 학습 세션은 문항별 풀이, 채점, 힌트 사용 등 순차적 상태 변화가 발생하므로 강력한 일관성(Strong Consistency)과 영속성이 요구됨.

## 결정 사항
1. **Durable Objects (DO) 단일 진실 공급원**
   - 각 학습 세션(`sessionId`)은 고유한 `StudySessionDO` 인스턴스에 매핑되어 세션 상태(진행도, attempts, 점수)를 전담 관리한다. 현재 배포 이력의 `new_classes`는 KV-backed DO이며, SQLite로 임의 변경하지 않는다.
2. **KV 전역 메타데이터 캐시**
   - 세션 생성 시 기본 메타데이터를 `KAGEMORI_KV`에 기록하여 엣지 전역에서 초저지연 상태 확인 및 캐싱을 지원함.
3. **Graceful Fallback & 포트 어댑터**
   - 명시적 로컬 모드 또는 바인딩 없는 테스트에서만 In-Memory 어댑터를 사용한다. 운영 DO 장애·누락 시 다른 저장소로 대체하지 않는다.

## 결과 및 영향
- 세션이 없으면 404, 저장소 장애는 503, 동시 수정 충돌은 409로 구분한다. 세션 ID만으로 풀이 상태를 재생성하지 않는다.

## 저장소 안정성 보완 (2026-09-26)

- DO의 `session` 키를 보존하고 별도 `revision` 키(기존 세션은 0)로 버전을 관리한다. 읽기 및 버전 비교·쓰기 모두 storage transaction으로 처리한다. 저장 성공 후에만 응답하며 메모리 캐시는 제거한다.
- Worker의 HTTP fetch 단일 전송 방식과 5초 제한을 사용한다. 저장 시간 초과는 커밋 여부 미확정이므로 성공으로 반환하지 않는다. 같은 문항·보기·힌트 조건 재제출은 기존 답안을 재사용하고, 다른 답으로 변경하면 409를 반환한다.
- KV에는 신규 세션의 불변 메타데이터만 성공한 DO 저장 뒤 `waitUntil`로 최선 노력 저장한다. 제한 시간·오류 로그를 두고 KV 상태를 세션 복원에 사용하지 않는다. 기존 `session_state:*`는 읽지 않으며 기존 TTL로 만료시킨다.
- D1은 교재·출제기준 및 전체 풀이·누적 진도 저장소다. 개인용 홈페이지의 공통 기록으로 집계하며 브라우저나 기기별로 나누지 않는다. 세션 진행은 DO가 전담한다. 문항은 현재 시드 데이터다.
- DO는 답안 저장과 D1 반영 예약(alarm)을 같은 transaction으로 기록한다. alarm은 D1에 문항별 답안을 멱등 삽입하고 실패 시 예약을 유지한다. D1 반영 전까지는 DO가 미반영 기록을 보유한다. 세션 조회 시 기존 DO 기록도 반영 예약하여 점진적으로 이관한다.
- D1 진도 API는 문항별 최신 채점 결과를 반환한다. 화면은 서버 조회 및 주기적 갱신만 사용하며 localStorage 기록을 채점 근거로 가져오지 않는다. D1 오류는 0%나 정적 자료로 대체하지 않는다.
- D1 바인딩이 있으면 실패·미초기화 상태를 503으로 노출한다. 카탈로그의 정적 자료는 로컬/테스트에서만 사용한다.
- 운영 모드는 Wrangler 변수로 명시한다. DO와 D1의 필수 바인딩 누락을 요청 경계에서 탐지한다. 오류 응답은 요청 식별자·안정된 코드와 재시도 가능 여부를 포함하며 원본 예외는 로그에만 남긴다.
- D1 풀이 테이블 마이그레이션을 추가하고 로컬에서 검증한다. 원격 적용과 배포는 실행하지 않는다. 기존 KV 전용 기록의 자동 이관은 일관성을 증명할 수 없어 하지 않는다.
- 근거: [DO transactions](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/), [KV consistency](https://developers.cloudflare.com/kv/concepts/how-kv-works/).

## 다음 문제 조회 복구 (2026-09-26)

- `/next`는 한 번 조회한 세션으로 문제와 진행 정보를 계산하여 DO/KV 중복 조회를 피한다.
- 클라이언트의 읽기 전용 `/next`는 시도당 10초, 전체 22초 제한 안에서 시간 초과·일시적 서버 오류를 1회 재시도한다. 제출 POST에는 이 정책을 적용하지 않는다.
- 조회 성공 전에는 이전 선택·힌트·해설을 보존한다. 최종 실패 시 같은 세션에서 다시 불러올 수 있으며, 첫 문제 조회 실패도 재시작 없이 복구한다.
- 조회 중 중복 요청을 막고, 세션 초기화 후 도착한 응답은 화면에 반영하지 않는다.

## AI 응답 캐시 (2026-09-27)

- 힌트·해설의 Gemini 성공 응답을 `KAGEMORI_KV`의 `ai:` 키에 30일간 저장해 같은 입력의 재호출 비용을 없앤다. 키는 모델·출력 토큰·프롬프트 전문의 SHA-256이므로 문항·개념·프롬프트·모델이 바뀌면 자동으로 새 키가 된다.
- 폴백 응답은 캐시하지 않는다. KV 조회·저장은 1초 제한의 최선 노력이며 실패해도 AI 호출과 응답을 막지 않는다. 세션·진도 판단에는 사용하지 않는다.
