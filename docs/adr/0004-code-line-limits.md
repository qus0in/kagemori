# ADR 0004: 코드 및 파일 라인 수 상한선(128줄/1000줄) 검사 및 모듈화 개선

## 상태
승인됨 (2026-09-26)

## 맥락
- 단일 책임 원칙(SRP)과 클린 아키텍처 원칙을 지속적으로 유지하려면 파일과 함수의 크기 비대화를 방지하는 구체적 기준이 필요함.
- AI 에이전트 및 협업 환경에서 모듈이 커지면 맥락 인지 한계, 병합 충돌, 인지 부하가 증가함.

## 결정 사항
1. **128줄 기준 (Soft/Modular Limit)**
   - 개별 함수/메서드/컴포넌트 단위는 128줄을 넘지 않는다.
   - `src/` 내 모듈(소스 파일)은 128줄 이하를 유지하도록 권장하며, 128줄 초과 시 분할 검토 경고(Warning) 및 분할 가이드를 제공한다.
2. **1000줄 기준 (Hard Limit)**
   - 프로젝트 내 모든 소스, 테스트, 문서 파일은 1000줄을 절대 초과할 수 없다(Hard Limit).
   - 1000줄 초과 파일 발견 시 CI 및 검사 스크립트는 실패(Exit Code 1)한다.
3. **검사 및 개선 자동화 (`check-line-limits.ts`)**
   - `pnpm check:lines` 스크립트를 추가하여 라인 수 검사 및 초과 파일 리팩토링 제안을 자동화한다.
   - 단일 책임 모듈화 스킬 `code-line-limits`를 정의하여 개선 절차를 체계화한다.

## 결과 및 영향
- 장점: 모든 모듈의 크기가 작게 유지되어 테스트 용이성, 유지보수성, 가독성이 극대화됨.
- 주의: 무분별한 파일 분할을 피하고 클린 아키텍처 레이어(domain/app/infra/ui) 기준에 맞춰 분할함.
