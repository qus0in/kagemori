- 작성일: 2026-09-25 (Asia/Seoul)
- 상태: 설계, 구현 및 데이터 수집 전
- 결정: [ADR 0003](../adr/0003-adaptive-question-rag-study.md)

## 1. 사용 흐름과 세 가지 출제 목적

첫 화면에는 D-day와 `문제 풀기`를 둔다. 교재 목차와 출제기준은 출제·설명·결과의 내부 분류로 활용한다. 학습자는 **한 번에 한 문제**를 보고, 필요하면 `개념 설명`을 열고, 답을 제출한 다음 해설과 근거를 본다. `다음 문제`를 누르면 그때 다음 한 문제를 받는다. 결과에는 강한 개념, 보완할 개념, 다음 학습 제안을 제시한다. 세 목적은 내부 정책이며 사용자에게 복잡한 모드 선택을 강요하지 않는다.

| 목적 | 들어가는 단계 | 문항 선택 | 힌트와 결과 | 완료 판단 |
| --- | --- | --- | --- | --- |
| 실력 체크 | 첫 방문, 새 출제기준, 진단 유효기간 경과 | 17개 세부과목의 최소 표본을 먼저 채우고, 나머지는 세부과목 문항 배분에 비례. 검증된 문제 중 처음 보는 문제 우선 | 설명 요청 가능하나 힌트 전 최초 답만 독립 진단에 사용. 힌트 후 정답은 학습 기록으로 분리 | 모든 세부과목에 표본이 있으면 초벌 진단. 표본이 적은 범위는 `판단 보류` |
| 실력 향상 | 체크 후, 또는 약점이 발견된 때 | 세부과목 배분 × 약점 × 최근 오답 × 미진단 범위 × 간격 복습. 과락 위험 과목을 먼저 보강 | 답 전 개념 설명 허용. 오답 개념을 쉬운 설명·다른 문항·재시도로 연결 | 서로 다른 문제에서 힌트 없는 정답이 반복되면 숙달 후보. 재검 전에는 확정하지 않음 |
| 시험 통과 점검 | 전 범위에 충분한 검증 문항이 쌓인 뒤 | 적용 출제기준의 100문항 구성과 과목별 20/30/50, 세부과목 배분을 재현. 비생성 문항 우선 + `VERIFIED` 등급 저장 AI 문항을 혼합 상한(40%) 이내 혼합. 실측 장·절 빈도는 충분한 증거가 있을 때만 세부 선택에 사용 | 120분 시간제한을 현재 조사값으로 두되 공식 대조 전에는 잠정. 제출 전 힌트·정답·해설 없음 | 전체 70개 이상, 각 과목 8/12/20개 이상을 별도로 판정. 출제기준이 잠정이면 `연습 결과`로만 표시 |

체크용 첫 세션의 목표는 최소 17문항(세부과목당 1문항)을 **순서대로 한 문제씩** 푸는 것이다. 이것만으로 강약을 단정하지 않는다. 후속 진단은 미진단 세부과목과 표본 부족 영역을 우선 채운다. 고정 문항 수·숙달 임계값·복습 간격은 검증 후 설정값으로 조정한다. 문제은행이 부족하면 같은 문항 반복으로 시험 점검을 채우지 않고 해당 목적을 `준비 중`으로 둔다. 사용자의 준비 상태와 시험 합격 가능성은 동일한 지표로 취급하지 않는다.

### 한 문제씩 진행하는 세션 규칙

- 한 세션에는 활성 문제가 최대 하나다. 서버는 현재 문제 ID·순번·상태를 보존하며 클라이언트에는 현재 문제와 선택지만 보낸다. 다음 문제 목록과 정답은 미리 보내지 않는다.
- `문제 표시 → (선택적으로 개념 설명) → 답 제출 → 결과 확인 → 다음 문제` 순으로 진행한다. 답을 제출하기 전에는 다음 문제로 넘어가지 않는다. 새로고침·재접속 시 같은 활성 문제를 복원하고 중복 제출은 한 번으로 처리한다.
- 실력 체크·향상에서는 제출 뒤 그 문제의 정답·해설·근거를 공개한다. 시험 통과 점검에서는 답을 잠그고 다음 문제로 이동하며, 정답·해설은 전체 세션 종료 후 공개한다.
- 시험 점검의 100문항은 한 화면에 차례로 1문항씩 제시하는 **전체 세션 길이**다. 시간은 세션 전체에 적용한다. 중도 종료는 미완료로 기록하고 합격 판정에 포함하지 않는다.

## 2. 출제 빈도와 선별 규칙

빈도의 단위는 `세부과목 배분`, `회차별 관측 문항`, `외부 분석 주장`으로 구분한다. 현재 D1의 17개 세부과목·100문항 값은 제3자 안내를 바탕으로 한 `PROVISIONAL` 출제 배분이다. 공식 출제표와 대조하기 전에는 확정값으로 표기하지 않는다. 125개 Chapter, 456개 SECTION의 수나 순서를 출제 확률로 바꾸지 않는다.

1. **기본 가중치:** 적용 출제기준의 세부과목별 배분 `q_t / 100`. 이것은 시험 구성의 초기 대리값이며 실제 출제 횟수가 아니다.
2. **관측 빈도:** 식별 가능한 회차·문항·출처·분류 근거를 확보할 때만 해당 세부과목/개념의 관측값을 계산한다. 전체 회차 수, 해당 범위에 분류 가능한 문항 수, 복수 태그 처리 방식, 표본 기간을 함께 저장한다. 동일 복원문항의 중복과 범위 변경을 제거한다. 표본이 부족하거나 분류가 다투어지면 가중치에 반영하지 않고 `근거 부족`으로 둔다.
3. **개인별 보정:** 실력 향상 목적에서만 힌트 없는 첫 답의 오답, 오래된 성공, 미진단 범위를 반영한다. 힌트 후 정답은 숙달을 증명하지 않는다. 한 세부과목을 과도하게 반복하지 않도록 탐색 하한과 최근 문항 중복 제한을 둔다.
4. **시험 점검:** 과목·세부과목 쿼터를 먼저 고정한다. 문항 원천은 비생성 문항 우선, `VERIFIED` 등급 저장 AI 문항만 혼합 상한 이내로 섞는다(ADR 0003). 관측 장·절 빈도가 검증되면 쿼터 내부의 문제 선택에만 반영한다. 개인별 약점은 모의시험 배분을 바꾸지 않는다.

운영 가능한 초기 규칙의 예시는 `학습 점수 = q_t × (1 + 약점 보정) × 복습 필요도`이며, 미진단 범위·과락 위험은 별도 우선 순위로 끼워 넣는다. 계수는 제품 가정이며 공식 빈도 추정치가 아니다. 매 세션에 선택 이유(`배분`, `약점`, `복습`, `미진단`)를 기록해 편향을 검토한다. 관측 빈도 계산은 수집된 회차가 충분할 때 표본 기준을 정하고 공개한다. 현재는 장·절 빈도 점수를 계산하지 않는다.

## 3. 자료와 문제 제작 파이프라인

| 단계 | 입력과 처리 | 저장·출시 게이트 |
| --- | --- | --- |
| 출처 선정 | 금융투자협회 시험 안내, 법령 원문, 금융감독원·KRX 등 기관 공개 자료 후보를 URL 단위로 조사 | 작성기관, 확인일, 적용일, 이용 조건, 실제 접근 가능 여부 기록. 공개 열람만으로 원문 재배포를 허용하지 않음 |
| 개념 구성 | 자료의 핵심 사실을 독립된 개념 단위로 재구성. 정의·조건·반례·계산 예를 구분 | 각 사실을 근거 URL·문서 위치에 연결. 법령·세제에는 기준일을 지정. 근거가 없거나 충돌하면 보류 |
| 검토·발행 | Gemma 4(`gemma-4-26b-a4b-it`, `gemma-4-31b-it`) 초안 및 Gemini 3.8 Flash 검증에 대해 근거 대조, 수치·단위·정의·시점·유사 문장 확인 | `draft → reviewed → published` 상태. 검토자/방법/버전 기록. 실제 검토 역량이 부족하면 자동 검증만으로 `reviewed` 처리하지 않음 |
| 임베딩 | 발행된 자체 개념 설명을 의미 단위로 분할해 `Gemini Embedding 2`(768차원, Cosine)로 임베딩 | 모델명·차원·본문 해시·버전 기록. 변경 시 해당 벡터 재생성; 다른 임베딩 모델 벡터 혼합 금지 |
| 문제은행 | 발행 개념에서 객관식 문제·선택지·정답·해설·출처를 구조화된 출력으로 초안 작성. 설명용 도표는 `gemini-3.1-flash-lite-image`(Nano Banana 2 Lite) 활용 | 정답 단일성, 오답의 타당성, 계산 검산, 출처, 난도, 중복, 최신성 검토 후 발행. 기출 원문 무단 저장·재게시 금지 |

문항은 `개념 이해`, `적용`, `계산`, `규정 판별` 같은 유형을 갖는다. 출제기준 세부과목과 개념의 연결은 검증 상태를 남긴다. 기존 `topic_chapters`의 `PROVISIONAL` 매핑을 확인 없이 확정 연결로 승격하지 않는다. SECTION 원문 대조가 끝나지 않은 영역은 Chapter/세부과목 수준에서 연결하거나 미매핑으로 둔다.

## 4. RAG 요청과 저장소 책임

`브라우저 → Hono Worker → D1(문항·개념 ID) → Gemini Embedding 2 → Vectorize(또는 로컬 Orama) 검색 → D1(발행 본문·출처) → gemini-3.5-flash-lite(또는 Gemini 3.8 Flash) 설명 → 브라우저` 흐름이다. 현재 문항의 개념 ID가 이미 결정되어 있으면 D1에서 그 개념을 먼저 가져오고, 관련 개념 확장이 필요할 때 벡터 검색을 수행한다. 질문이 자유형이면 세부과목·판본 필터로 검색 범위를 좁힌다. 검색 결과에 근거가 없으면 모른다고 응답하고 임의 설명을 만들지 않는다. 모델의 인용 표시는 D1에서 실제 반환한 출처와 대조한다.

- **D1:** 출처, 개념 원문·버전, 문제·선택지·정답, 세부과목 연결, 관측 빈도 근거, 학습 세션·답안·숙달 집계의 기준 저장소. 기존 `sources`, `exam_topics`, `chapters`, `sections`와 연결하되 판본·검증 상태를 유지한다.
- **Vector Search (Vectorize & Orama):** 발행 개념 청크의 임베딩과 D1 청크 ID, 필터용 메타데이터 보관.
  - 프로덕션: **Cloudflare Vectorize** (에지 네이티브 인덱스, 768차원, Cosine)
  - 로컬/테스트 대역: **`@orama/orama`** (TypeScript/JavaScript 생태계의 표준 경량 임베디드 벡터 및 하이브리드 검색 라이브러리). Clean Architecture `VectorSearchPort`로 추상화하여 로컬 Vite 개발 및 Vitest/Node 테스트에서도 외부 의존성 없이 동일한 코사인 유사도 검색과 필터링을 검증한다.
- **Worker:** AI Studio API 키를 secret으로 사용하여 Gemini API를 직접 호출.
  - 실시간 세션 서빙: 힌트·일반 해설·구조 도식은 `gemini-3.5-flash-lite` 작성 → Gemma 26B 품질 검토 → 미달/실패 시 `gemini-3.8-flash` 보정. 사용자 해설 재요청·출제·1차 검수는 3.8 직행(ADR 0003).
  - 심층 추론/검증: 1M 컨텍스트와 사고 능력을 갖춘 `Gemini 3.8 Flash` 적용
  - 시각 자료 생성: `gemini-3.1-flash-lite-image`(Nano Banana 2 Lite) 적용
  - 요청 제한, 비용 상한, 시간 초과, 응답 스키마 검증, 정답 비공개를 Worker에서 통제한다.

개념 설명의 검색 품질은 대표 질문 세트로 관련 청크 적중, 잘못된 개념 혼입, 출처 연결, 근거 없음 처리까지 확인한다. 벡터 유사도는 정답의 신뢰도나 학습자의 실력 점수가 아니다.

## 5. 데이터 모델 확장안

| 논리 엔터티 | 핵심 필드 | 목적 |
| --- | --- | --- |
| `source_documents` | `source_id`, `title`, `url`, `publisher`, `checked_at`, `effective_at`, `usage_terms`, `status` | 기존 `sources`와 연결되는 실제 자료·이용 조건 |
| `concepts`, `concept_versions`, `concept_sources` | `concept_id`, `topic_id`, `chapter_id?`, `section_id?`, `body`, `status`, `version`, `source_id`, `locator`, `reviewed_at` | 자체 작성 설명과 근거·판본·검토 이력 |
| `concept_chunks` | `chunk_id`, `concept_version_id`, `body_hash`, `embedding_model`, `dimension`, `vector_id`, `index_status` | D1 본문과 Vectorize 벡터 동기화 |
| `questions`, `question_options`, `question_concepts` | `question_id`, `version`, `topic_id`, `type`, `difficulty`, `status`, `correct_option_id`, `explanation`, `concept_id`, `source_id` | 검증된 문제은행과 정답·출처. 답안 응답 API에서 정답 필드 제외 |
| `practice_sessions`, `attempts` | `learner_id`, `purpose`, `blueprint_id`, `question_id`, `question_version`, `first_answer`, `final_answer`, `hint_used`, `answered_at`, `duration` | 독립 진단과 힌트 후 학습의 분리, 동일 문항 반복 추적 |
| `mastery_snapshots` | `learner_id`, `concept_id`, `topic_id`, `evidence_count`, `confidence`, `last_seen_at`, `next_review_at` | 빠른 추천용 집계; 원자료는 `attempts` |
| `observed_items`, `frequency_reports` | ADR 0002의 회차·문항·분류·출처·표본 필드 | 실제 관측 빈도의 근거와 재현 가능한 집계 |

초기에는 계정 없이 불투명한 학습자 ID를 보안 쿠키로 발급하는 방안을 검토한다. 다중 기기 동기화가 필요하면 별도 인증 결정을 추가한다. 풀이 이력 보존 기간과 삭제 기능을 구현 전에 정한다. 임베딩과 학습 이력은 분리하며 개인정보를 Gemini 프롬프트에 싣지 않는다.

## 6. 단계별 구현·검증 게이트

1. **출처와 시험 기준 확인:** 2026 적용 공식 과목표·시험시간·합격 기준을 대조한다. 공개 자료 후보별 이용 조건과 시점 확인. ADR 0002의 2단계 범위·출처를 사용자와 재확인한다.
2. **좁은 콘텐츠 파일럿:** 세부과목 하나에서 개념·근거·문제 제작 및 검토 기준을 확립한다. 문항과 개념의 연결, 애매한 정답, 오래된 규정을 검출한다.
3. **저장·검색:** D1 마이그레이션, Vectorize 인덱스·메타데이터 필터, 임베딩 배치 작업과 재시도/재색인 절차를 만든다. 본문 해시와 벡터 ID 대조로 누락을 찾는다.
4. **실력 체크:** 진단 세션·문제 제출 API, 힌트 사용 분리, 표본 부족 표시, 기본 강약점 계산을 만든다. 처음 보는 문제와 재풀이 문제를 구분한다.
5. **실력 향상:** 개념 설명 RAG, 출처 표시, 약점·복습 추천, 근거 없는 설명의 중단 동작을 검증한다. 학습자별 개선은 힌트 없는 새 문항의 재평가로 확인한다.
6. **시험 통과 점검:** 검증된 전체 범위의 충분한 문항 확보 후 100문항·과목별 쿼터·시간·과락·총점 계산을 구현한다. AI 문항은 `VERIFIED` 등급만 혼합 상한 이내로 섞는다. 잠정 출제기준에서는 공식 합격 예측 표현을 쓰지 않는다.
7. **운영 평가:** 문제별 오류 신고·철회, 법령 변경 재검토, 콘텐츠 버전 이동, 검색 적중률, 세부과목별 문항 부족, AI 호출량과 비용을 점검한다.

테스트는 도메인의 출제 쿼터·점수·과락·힌트 반영 규칙, 앱의 세 목적 전이, 인프라의 D1/Vectorize/Gemini 어댑터 계약, UI의 정답 비공개·근거 표시를 나눠 검증한다. `pnpm check`, `pnpm test`, `pnpm build`는 구현 단계의 기본 게이트다. 이 문서는 설계만 기록하며 리소스 생성·배포·커밋을 수행하지 않는다.
